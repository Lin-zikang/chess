# 官方题库目录说明

本目录仅用于存放 Chess 项目的官方加密谜题文件及其公开清单。

## 文件要求

- 谜题文件扩展名必须为 `.txt`。
- 文件内容必须由项目内置的谜题导出功能生成，不应手工修改加密正文。
- 谜题文件名、`manifest.json` 和本说明文件统一使用 UTF-8 编码。
- 谜题加密文件逻辑保持不变；`manifest.json` 仅独立登记编创者信息，正式版权声明由前端自动生成。
- 现有官方谜题的编创者统一登记为 `Ye.Yinfeng`，谜题编创者版权所有。

## `manifest.json` 格式

```json
{
  "schemaVersion": 2,
  "files": [
    {
      "file": "谜题文件名.txt",
      "title": "页面显示标题",
      "description": "可选的谜题说明",
      "creator": "Ye.Yinfeng"
    }
  ]
}
```

页面会在官方谜题列表中显示 `creator`，进入谜题后由 JavaScript 自动生成对应的完整版权声明；正式清单不需要也不应重复填写 `copyright`。清单中的文件名必须与实际文件名完全一致，包括中文、空格、符号及大小写。

## 文件发现方式

页面会优先读取根目录 `site-config.js` 中的 `officialFiles`，随后读取本目录的 `manifest.json`。若部署服务器支持目录索引，页面也会尝试自动发现 `.txt` 文件；GitHub Pages 自定义域名部署则建议配置 `officialRepository`。

正式发布环境应优先维护 `manifest.json`，以保证每个谜题都有明确、可核对的编创者标识，并由统一前端逻辑生成正式版权声明。目录索引或 GitHub API 自动发现仅作为兼容方式；通过这些方式发现且未附带元数据的谜题，程序默认显示编创者 `Ye.Yinfeng`。

## 编码与发布检查

发布前应确认：

1. 所有中文文件名可在文件系统与 ZIP 压缩包中正常显示；
2. `manifest.json` 可按 UTF-8 正常解析；
3. 每个 `file` 字段均能对应到同名 `.txt` 文件；
4. 加密 `.txt` 文件正文未被编辑或重新格式化；
5. 页面列表与挑战页面均能根据 `creator` 正常显示统一生成的谜题编创者版权声明。
