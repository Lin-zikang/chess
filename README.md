# Chess 国际象棋

Chess 是一个纯前端国际象棋网页应用，提供双人对弈、云端 AI 对弈、棋局库、已结束棋局复盘、谜题挑战与谜题制作功能。项目可直接部署到 GitHub Pages 或其他静态网站服务，不要求后端数据库。

平台程序 © 2026 Lin.Zikang，保留所有权利。  
官方题库通过 `official_levels/manifest.json` 逐题登记编创者；现有谜题的编创者均为 Ye.Yinfeng。正式版权声明由前端依据 `creator` 信息自动生成，官方谜题不显示正确解答。

## 功能概览

- **双人对弈**：支持标准开局、自定义局面、悔棋、和棋、认输与自动保存；棋局正式结束后方可进入逐步复盘。
- **AI 对弈**：通过 StockfishOnline 云端接口计算着法，无需用户填写 API Key；提供 Depth 11、13、15 三档搜索深度，并支持受控悔棋。悔棋会回到玩家最近一次落子之前，每次重新落子后仅可执行一次。
- **棋局库**：双人及 AI 对局保存在当前浏览器的 `localStorage` 中，可继续未完成棋局、修改名称或删除记录；未完成棋局的复盘按钮保持灰度禁用。
- **严格复盘**：仅对已结束且包含着法记录的棋局开放，以 Depth 15 实时分析当前局面，并根据实战着法与引擎最佳着法的评价差，显示 `!`、`✓`、`?!`、`?`、`??` 等近似走法质量标记。
- **谜题训练**：支持官方加密题库与个人题库；官方谜题列表和挑战页面正式显示编创者及自动生成的版权信息，且不展示正确解答。
- **落子动画**：对弈、AI、谜题与错误回退共用全局滑动逻辑；每一着内部保持匀速直线运动，远距离走子会平滑提速，斜向走子按更长路径获得额外速度补偿，因此不同走法既非统一速度，也非统一时长。
- **谜题判定**：挑战者落子滑动到目标格后执行 0.2 秒判定；错误走法原路滑回，正确走法判定完成 0.3 秒后由对方按预设回子。
- **谜题制作与分享**：可摆放初始局面、录入完整解法，并通过 UTF-8 编码的 `.txt` 加密文件导入或导出。
- **响应式界面**：亮色蓝色主题，顶部采用可展开的灵动岛导航，适配手机、平板和桌面浏览器。

## AI 接口与搜索深度

AI 每一步通过云端接口实时请求，仅使用 StockfishOnline 云端接口，并按所选深度实时计算。不会使用本地随机走法。

项目调用以下云端接口：

```text
https://www.stockfish.online/api/s/v2.php
```

请求使用当前局面的完整 FEN 与指定深度。可选深度如下：

| 档位 | 深度 | 适用场景 |
| --- | ---: | --- |
| 快速 | 11 | 移动网络或需要更快响应时 |
| 均衡 | 13 | 默认 AI 对弈 |
| 严格 | 15 | 更高强度对弈与对局复盘 |

复盘固定使用 Depth 15，且仅在棋局状态为“已结束”并存在着法记录时开放。未完成棋局不会发起复盘分析请求，其复盘按钮以灰度禁用状态显示。第三方接口可能受到网络、限流或服务状态影响；接口不可用时，页面会明确提示重新分析或重试，不会伪造计算结果。

### AI 对弈悔棋规则

AI 对局中的悔棋按照以下规则执行：

- 点击“悔棋一步”后，棋局回退到玩家最近一次落子之前，并恢复为玩家走棋。
- 每次玩家重新落子后仅可悔棋一次；完成悔棋后，必须先重新落子，不能连续悔棋。
- AI 云端请求、计算及落子动画进行期间，悔棋按钮保持禁用，避免异步结果覆盖已回退的棋局状态。
- 若云端 API 调用失败且 AI 尚未落子，允许撤销玩家刚才的着法，同样回退到该次玩家落子之前。
- 若 AI 已正常落子，悔棋会同时撤销玩家最近一着及其后的 AI 回应，从而确保回退后仍由玩家走棋。

悔棋可用状态随 AI 棋局一并保存到浏览器本地数据中；刷新页面或重新进入未完成棋局后，程序仍会遵守“不能连续悔棋”的限制。

## 对局复盘使用规则

为确保复盘结果对应完整、确定的对局记录，系统统一执行以下规则：

- 双人对弈和 AI 对弈均须在棋局正式结束后方可进入复盘或启动 AI 分析。
- 对于状态为“未完成”的棋局，所有“复盘”“复盘分析”及“复盘 / AI 分析”按钮均以灰度禁用状态显示，且不可点击。
- 程序在复盘入口及分析执行层同时校验棋局状态，避免通过非界面方式绕过限制。
- 已结束但没有任何着法记录的棋局不进入逐步复盘，以避免生成无实际对局内容的分析页面。

## 本地数据与分析缓存

应用使用浏览器 `localStorage` 保存棋局、谜题、挑战进度及引擎分析缓存。引擎缓存具有以下约束：

- 缓存键同时包含缓存版本、完整 FEN 与准确搜索深度，不会混用不同局面或不同深度的结果。
- 只缓存成功且通过合法着法校验的分析结果，错误响应不会进入缓存。
- 缓存设置有效期和最大条目数，并按最近使用时间清理，避免无限增长。
- 相同局面与深度的并发请求会合并，复盘切换步骤时会校验请求令牌，避免旧请求覆盖新局面。
- 本地数据读取失败、JSON 损坏或存储空间不足时会安全降级，不会阻止页面启动。

清除浏览器站点数据、使用无痕模式或更换设备后，本地棋局与谜题不会自动同步。请勿将本地缓存视为永久备份。

## 复盘走法评价说明

走法标记根据同一搜索深度下的引擎评价差近似生成：

- `!`：最佳或非常精准的着法
- `✓`：优秀着法
- `?!`：值得商榷，存在一定评价损失
- `?`：明显失误
- `??`：严重失误

该标记用于训练参考，并非 Chess.com 官方 Game Review 结果，也不代表赛事裁判结论。将军、将死、逼和、五十回合规则和子力不足等终局会优先由本地规则引擎判定。

## 官方题库文件与版权清单

官方加密谜题必须放在：

```text
official_levels/
```

文件名必须以 `.txt` 结尾，例如：

```text
official_levels/一步杀王 01.txt
```

页面按以下顺序发现官方题库文件：

1. `site-config.js` 中的 `officialFiles`；
2. `official_levels/manifest.json`；
3. 服务器目录索引；
4. GitHub API 仓库目录。

正式发布时应维护 `official_levels/manifest.json`，为每个谜题明确记录文件名、显示标题与编创者。版权声明由 JavaScript 根据 `creator` 自动补全，清单无需重复维护 `copyright` 字段。现行正式格式如下：

```json
{
  "schemaVersion": 2,
  "files": [
    {
      "file": "一步杀王 01.txt",
      "title": "一步杀王 01",
      "description": "官方入门训练。",
      "creator": "Ye.Yinfeng"
    }
  ]
}
```

`creator` 会显示在官方谜题列表中；进入谜题后，页面会由前端自动生成对应的完整版权声明。正式清单不再填写 `copyright`。若旧清单未填写 `creator`，程序默认使用 `Ye.Yinfeng`；旧数据中的 `copyright` 字段仍可兼容读取。

### 在 `site-config.js` 中登记

```js
window.CHESS_SITE_CONFIG = {
  officialFolder: 'official_levels',
  officialFiles: [
    {
      file: '一步杀王 01.txt',
      title: '一步杀王 01',
      creator: 'Ye.Yinfeng'
    }
  ],
  officialRepository: '',
  officialBranch: 'main'
};
```

许多静态网站不会开放目录索引。使用自定义域名部署到 GitHub Pages 时，请在 `site-config.js` 中填写：

```js
officialRepository: 'GitHub用户名/仓库名'
```

并确认 `officialBranch` 与实际发布分支一致。

## 加密文件兼容性

谜题 `.txt` 文件继续使用项目原有的 AES-GCM／XOR 兼容封装、密钥派生参数、文件标识和导入导出流程。本次正式版权清单与全局滑动算法调整不改变谜题加密文件逻辑，也不要求重新生成现有加密谜题正文。

请勿手工修改加密 `.txt` 文件中的 `magic`、`version`、`iv` 或 `data` 字段。谜题编创者信息由 `manifest.json` 负责标注，避免影响既有加密文件兼容性。

## 部署与编码

项目不需要构建步骤。将仓库内容原样发布为静态站点即可。建议通过 HTTPS 部署，以确保浏览器可以正常访问云端分析接口和 Web Crypto API。

所有源码、Markdown、JSON、中文文件名与谜题清单均使用 UTF-8 编码。请勿使用会自动转换为 ANSI、GBK 或其他编码的编辑器保存文件。压缩或解压时应保留 ZIP 的 UTF-8 文件名标志，以免中文文件名出现乱码。
